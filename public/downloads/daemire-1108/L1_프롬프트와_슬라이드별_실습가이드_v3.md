# 강연 1 실습가이드 v3 — CRM 데이터를 경영 판단으로 바꾸기

> 청중용 따라하기 문서입니다. 화면에서 원장님이 시연하는 것을 본 뒤, 아래의 1·2·3 순서대로 직접 수행하세요. 

## 준비 파일

- `2026년10월_방문시술매출_CRM.xlsx`: 방문·시술·금액·재방문·유입채널이 들어 있는 CRM 표
- `2026년10월_상담문의_목록.csv`: 상담 문의 96건
- `L1_지표정의_결정카드_템플릿.md`: 지표를 어떤 기준으로 계산할지 기록
- `L1_검산과_데이터품질_체크리스트.md`: 계산과 데이터 오류 확인

## 실습 전 용어 5개

- **CRM:** 고객 상담, 예약, 방문, 결제 같은 기록을 모아 관리하는 시스템.
- **행:** 엑셀 표에서 가로 한 줄. 한 행이 환자 한 명인지 방문 한 번인지는 반드시 확인해야 한다.
- **열:** 이름, 방문일, 시술명, 금액처럼 세로로 나뉜 항목.
- **재방문율:** 정해진 기간 안에 다시 온 사람의 비율. 기간과 계산 대상을 먼저 정해야 한다.
- **전환율:** 문의한 사람 중 실제 예약 또는 방문으로 이어진 비율. 문의와 예약을 연결하는 기준이 있어야 계산할 수 있다.

## 슬라이드 1. 오늘 할 일 — 파일을 AI에게 읽혀 보기

**이 슬라이드에서 원장님이 보여주는 것**  
AI에게 파일을 첨부하고 “먼저 표 구조부터 설명하라”고 요청한다. 분석을 바로 시키지 않는 이유는 열의 뜻과 데이터 단위를 먼저 확인해야 하기 때문이다.

**내가 할 일 1·2·3**
1. `2026년10월_방문시술매출_CRM.xlsx`를 PC에 다운로드한다.
2. ChatGPT 대화를 열고 입력창 옆 파일 첨부 버튼을 누른다.
3. 파일을 선택한 뒤 아래 문장을 붙여넣고 전송한다.

**복붙 프롬프트**
```text
첨부한 엑셀은 100% 데이터입니다.
분석은 아직 하지 마세요.
먼저 시트 이름, 데이터 행 수, 열 제목을 확인해 주세요.
각 열이 무엇을 뜻하는지 쉬운 한국어로 설명하고, 한 행이 무엇을 의미하는지 데이터만으로 확인할 수 있는지 알려 주세요.
확인할 수 없는 내용은 추측하지 마세요.
```

**성공 예시**  
“방문시술매출 시트 200행. 방문일·시술·금액·재방문·유입채널 열이 있습니다. 한 행이 방문 1건인지 환자 1명인지는 중복 환자 식별 기준을 추가 확인해야 합니다.”처럼 구조와 한계를 함께 말한다.

**막히면**  
파일이 첨부되지 않으면 파일 첨부 버튼을 다시 눌러 파일을 선택한다. AI가 환자 수라고 단정하면 “행 수와 환자 수를 구분해 주세요”라고 추가 입력한다.

## 슬라이드 2. 문의 데이터 — 문의 유형이 몇 건인가?

**이 슬라이드에서 원장님이 보여주는 것**  
CSV 파일을 첨부해 문의 유형별 건수를 세고, 합계가 전체 96건인지 확인한다.

**내가 할 일 1·2·3**
1. `2026년10월_상담문의_목록.csv`를 다운로드한다.
2. 새 대화 또는 같은 대화에 파일을 첨부한다.
3. 아래 프롬프트를 붙여넣는다.

**복붙 프롬프트**
```text
첨부한 CSV는 상담 문의 96건입니다.
문의 유형별 건수를 세어 표로 보여 주세요.
유형별 건수의 합이 96건인지 확인하고, 각 유형의 비율도 계산해 주세요.
예상 분포는 48건, 12건, 8건, 28건입니다.
실제 집계가 예상과 다르면 숫자를 억지로 맞추지 말고 차이를 알려 주세요.
```

**성공 예시**  
4개 유형이 각각 48·12·8·28건이고 합계가 96건이라고 표시된다. 비율은 각각 50.0%, 12.5%, 약 8.3%, 약 29.2%다.

**막히면**  
AI가 분류명을 바꾸면 “원본 CSV의 분류명을 그대로 사용하세요”라고 한다. 합계가 96이 아니면 중복 행이나 빈 행이 있는지 확인해 달라고 요청한다.

## 슬라이드 3. 데이터 품질 — 중복과 누락 찾기

**이 슬라이드에서 원장님이 보여주는 것**  
분석 전에 데이터가 믿을 만한지 확인한다. 중복은 같은 기록이 두 번 들어간 것이고, 누락은 있어야 할 값이 비어 있는 것이다.

**내가 할 일 1·2·3**
1. CRM 엑셀 파일을 첨부한다.
2. 아래 프롬프트를 입력한다.
3. AI가 제시한 행 번호와 열 이름을 원본 엑셀에서 확인한다.

**복붙 프롬프트**
```text
첨부한 CRM 데이터의 품질을 점검해 주세요.
1. 완전히 똑같은 행이 있는지
2. 중요한 열에 빈칸이 있는지
3. 금액이 0원 또는 음수인 행이 있는지
4. 날짜 형식이 다른 행이 있는지
5. 재방문 값이나 유입채널처럼 정해진 선택지와 다른 값이 있는지
항목별 발견 건수와 해당 행 번호를 표로 보여 주세요.
문제가 없으면 없다고 말하고, 임의로 데이터를 수정하지 마세요.
```

**성공 예시**  
“금액 빈칸 2건, 날짜 형식 확인 필요 1건”처럼 건수와 위치가 표시된다. 문제가 없는 항목은 0건이라고 표시한다.

**막히면**  
행 번호가 실제 엑셀과 다르면 헤더 행 포함 여부를 확인한다. AI에게 “첫 번째 제목 행을 제외한 데이터 기준 행 번호도 함께 표시해 주세요”라고 요청한다.

## 슬라이드 4. 지표 정의 — 숫자를 세기 전에 기준 정하기

**이 슬라이드에서 원장님이 보여주는 것**  
같은 이름의 지표도 계산 방법이 다를 수 있다. 예를 들어 재방문율은 환자 수 기준인지 방문 건수 기준인지에 따라 결과가 달라진다.

**내가 할 일 1·2·3**
1. `L1_지표정의_결정카드_템플릿.md`를 연다.
2. 오늘 계산할 지표 하나를 고른다. 예: 재방문율.
3. 아래 프롬프트로 분모와 분자를 먼저 정리한다.

**복붙 프롬프트**
```text
CRM 데이터에서 재방문율을 계산하고 싶습니다.
계산하기 전에 다음을 쉬운 말로 정리해 주세요.
- 분자: 비율에서 위쪽에 들어가는 숫자
- 분모: 비율에서 아래쪽에 들어가는 전체 숫자
- 어떤 사람 또는 방문을 세는지
- 어느 기간을 기준으로 하는지
데이터에 필요한 정보가 없으면 계산하지 말고 부족한 정보를 알려 주세요.
```

**성공 예시**  
“재방문 환자 수 ÷ 첫 방문 환자 수”처럼 계산 기준이 문장으로 정리되고, 기간이 없으면 기간을 정해야 한다고 알려 준다.

**막히면**  
분모가 모호하면 결과 숫자를 요구하지 않는다. 먼저 병원에서 사용할 정의를 결정카드에 기록한다.

## 슬라이드 5. 유입채널 — 어디에서 문의가 들어오는가?

**이 슬라이드에서 원장님이 보여주는 것**  
인스타그램, 소개, 검색 등 유입 경로별로 문의나 방문 기록을 나눠 본다. 유입 건수가 많다는 사실만으로 매출 기여가 높다고 결론 내리면 안 된다.

**내가 할 일 1·2·3**
1. CRM 파일을 첨부한다.
2. 유입채널 열이 있는지 확인한다.
3. 아래 프롬프트로 채널별 건수와 금액을 따로 집계한다.

**복붙 프롬프트**
```text
CRM 데이터에서 유입채널별로 다음 숫자를 계산해 주세요.
1. 기록 건수
2. 결제금액 합계
3. 기록 1건당 평균 결제금액
표로 정리하고 전체 합계와 맞는지 확인해 주세요.
유입채널이 비어 있는 행은 별도 항목으로 표시하세요.
이 결과만으로 광고 효과가 좋다거나 나쁘다고 단정하지 마세요.
```

**성공 예시**  
채널별 건수·결제금액 합계·평균 금액이 각각 구분된다. 전체 합계와 채널별 합계가 일치한다.

**막히면**  
AI가 문의 수와 방문 수를 섞으면 “이 파일의 한 행이 의미하는 단위부터 다시 확인해 주세요”라고 한다.

## 슬라이드 6. 문의에서 방문으로 — 연결 가능한가?

**이 슬라이드에서 원장님이 보여주는 것**  
문의 파일과 CRM 파일을 합치려면 두 파일에 같은 의미의 연결 ID가 있어야 한다. 이름이 비슷하다고 같은 사람으로 판단하면 안 된다.

**내가 할 일 1·2·3**
1. CRM XLSX와 문의 CSV를 같은 대화에 모두 첨부한다.
2. 두 파일의 ID 열을 확인한다.
3. CRM 연결문의번호와 문의관리번호를 비교한다. 연결 30건을 확인하고 나머지를 억지로 채우지 않는다.

**복붙 프롬프트**
```text
첨부한 CRM 파일과 문의 파일을 비교해 주세요.
CRM 연결문의번호와 문의파일 문의관리번호를 서로 비교해 주세요. 연결된 행의 고객관리번호도 교차 검증하고, 미연결 행은 그대로 남겨 주세요.
CRM의 연결문의번호와 문의 CSV의 문의관리번호가 동일하고, 고객관리번호도 일치하는지 확인하세요. 일치하지 않으면 연결하지 마세요.
연결 가능한 경우에만 연결 전 행 수와 연결 후 행 수를 비교하고, 중복으로 행이 늘어나는지 점검해 주세요.
```

**성공 예시**  
“연결문의번호로 확인된 30건의 연결은 검토할 수 있지만, 미확인 기록의 전환 여부는 판단할 수 없습니다” 또는 “공통 ID 기준으로 연결했으며 연결 전후 행 수는 …”처럼 근거를 제시한다.

**막히면**  
AI가 임의로 이름·날짜를 조합해 연결하면 중단시킨다. 실제 병원에서는 승인된 내부 절차로 가명 연결키를 만든 뒤 분석한다.

## 슬라이드 7. 숫자에서 질문으로 — 무엇을 더 확인할까?

**이 슬라이드에서 원장님이 보여주는 것**  
데이터는 답을 자동으로 정해 주지 않는다. 데이터가 보여 주는 사실과 그럴듯한 설명을 구분해야 한다.

**내가 할 일 1·2·3**
1. 앞 단계에서 확인한 채널별 결과를 준비한다.
2. 아래 프롬프트를 입력한다.
3. 사실과 추측이 분리되어 있는지 읽는다.

**복붙 프롬프트**
```text
지금까지 계산한 결과를 바탕으로 관찰된 사실 3개를 적어 주세요.
각 사실마다 가능한 설명을 2개씩 제시하되, 설명은 아직 가설이라고 표시해 주세요.
가설을 확인하려면 어떤 추가 데이터가 필요한지 적어 주세요.
데이터만으로 알 수 없는 원인이나 인과관계를 사실처럼 말하지 마세요.
```

**성공 예시**  
“채널 A 기록 건수가 가장 많다”는 사실과 “광고비가 효율적일 수 있다”는 가설이 구분된다. 광고비나 신규 환자 여부가 없으면 추가 데이터가 필요하다고 말한다.

**막히면**  
답이 두루뭉술하면 “각 항목을 실제 병원에서 확인할 수 있는 숫자와 자료명으로 구체화해 주세요”라고 요청한다.

## 슬라이드 8. 경영 의사결정 — 작은 실험으로 바꾸기

**이 슬라이드에서 원장님이 보여주는 것**  
분석 결과를 곧바로 큰 정책 변경으로 연결하지 않고, 작게 시험하고 결과를 측정한다.

**내가 할 일 1·2·3**
1. 관심 있는 문제 하나를 고른다.
2. 아래 프롬프트를 입력한다.
3. 실행 전 기준 숫자와 실행 후 확인할 숫자를 기록한다.

**복붙 프롬프트**
```text
데이터에서 확인한 사실을 바탕으로 2주 안에 시험할 수 있는 작은 개선 실험 3개를 제안해 주세요.
각 실험마다 대상, 바꿀 행동, 기간, 시작 전 숫자, 종료 후 숫자, 성공 기준, 부작용 점검 항목을 적어 주세요.
실제 데이터로 효과가 확인되기 전에는 매출 상승을 보장한다고 표현하지 마세요.
```

**성공 예시**  
“문의 응답 시간을 기록하고 2주 동안 응답 절차를 바꾼 뒤 예약 전환을 비교”처럼 실행과 측정이 한 세트로 나온다.

**막히면**  
실험이 너무 크면 “직원 1명 또는 문의 유형 1개부터 시험하는 최소 규모로 줄여 주세요”라고 요청한다.

## 슬라이드 9. 결과 검산 — AI의 답을 그대로 믿지 않기

**이 슬라이드에서 원장님이 보여주는 것**  
합계, 행 수, 중복, 누락을 원본 파일과 대조한다. AI 답변을 복사해 쓰기 전에 숫자를 확인한다.

**내가 할 일 1·2·3**
1. `L1_검산과_데이터품질_체크리스트.md`를 연다.
2. AI가 계산한 합계와 원본 엑셀 합계를 비교한다.
3. 차이가 있으면 어떤 행이 원인인지 찾는다.

**복붙 프롬프트**
```text
방금 제시한 모든 집계 결과를 다시 검산해 주세요.
각 결과에 사용한 열, 계산식, 포함한 행 수, 제외한 행 수를 표시해 주세요.
금액 합계는 원본 데이터의 전체 합계와 비교해 주세요.
차이가 있으면 차이가 발생한 행을 찾고, 원인을 추측하지 말고 확인 가능한 근거를 제시해 주세요.
```

**성공 예시**  
각 숫자에 계산식과 사용 행 수가 붙고, 전체 합계가 원본과 일치하는지 확인된다.

**막히면**  
AI가 계산식 설명을 못 하면 해당 숫자를 최종 보고에 사용하지 않는다. 엑셀 피벗테이블이나 SUM 함수로 별도 확인한다.

## 슬라이드 10. 내 병원에 적용 — 개인정보 없이 시작하기

**이 슬라이드에서 원장님이 보여주는 것**  
데이터 실습을 실제 업무에 옮길 때는 개인정보를 제거하고, 필요한 항목만 남긴다.

**내가 할 일 1·2·3**
1. 실제 환자 이름·전화번호·차트번호가 없는 집계용 표부터 준비한다.
2. 병원 내부 승인 절차와 개인정보 보호 기준을 확인한다.
3. 아래 프롬프트로 필요한 열 구조만 설계한다.

**복붙 프롬프트**
```text
우리 병원 CRM 데이터를 분석하기 위한 익명화된 표 구조를 설계해 주세요.
환자 이름, 전화번호, 주소, 주민등록번호, 차트번호, 상담 원문은 수집하지 마세요.
필요한 분석 목적은 유입채널별 문의 수, 예약 수, 방문 수, 결제금액 합계입니다.
각 열의 이름, 의미, 예시 형식, 개인정보 위험, 입력 규칙을 표로 만들어 주세요.
```

**성공 예시**

**막히면**

## 현장 데이터가 들어오는 순서 — 강연 보충 설명

**상황 예시: 김민지가 인스타그램 DM으로 피코토닝 가격을 문의했다.**

1. **인스타그램 DM:** 상담 담당자가 DM을 확인한다. DM 대화에는 계정명·전송 시각·대화 내용이 있을 수 있지만, 병원 고객관리번호가 자동으로 생기는 것은 아니다.
2. **카카오톡 채널:** 상담이 카카오톡으로 이동하면 채널 안에서 별도 대화가 시작된다. 같은 사람이라는 사실은 자동으로 증명되지 않는다.
3. **네이버 예약:** 환자가 예약을 신청하면 예약내역·방문 예정일·예약상태가 남을 수 있다. 노출 항목은 병원 설정·서비스 권한에 따라 다르다.
4. **전화:** 통화 시각과 상담 메모를 직원이 기록한다. 전화번호는 직접 분석 자료로 내보내지 않는다.
5. **구글폼:** 직접 설계한 질문의 응답값과 제출 시각이 쌓인다. 폼 응답번호는 병원 고객번호와 다르다.
6. **베가스CRM:** 직원이 접수, 내원, 시술, 결제를 입력한다. 어떤 정보가 자동 입력되는지는 실제 설치 환경에서 확인해야 한다.

### 아이디 통합 시 가장 중요한 규칙

- `경로별접수번호`는 **실습 파일의 병원 내부 관리용 번호**다. 인스타그램·카카오톡·네이버가 실제 발급한 원본 ID 형식이라고 가정하면 안 된다.
- `문의관리번호`는 문의 1건을 가리키고, `고객관리번호`는 고객을 가리킨다. 같은 고객이 여러 번 문의할 수 있다.
- `연결문의번호`가 채워진 방문은 내부에서 연결을 확인한 경우다. 결측값은 '연결되지 않음'이 아니라 **확인할 수 없음**이다.
- 이름이나 날짜가 비슷하다는 이유로 연결하지 않는다. 원본 시스템에서 승인된 근거가 있어야 한다.

**추가 복붙 프롬프트**
```text
두 파일을 함께 읽어 주세요.
상담문의 CSV의 문의관리번호와 방문시술매출 시트의 연결문의번호를 연결하세요.
반드시 고객관리번호가 양쪽에서 같을 때만 연결 성공으로 표시하세요.
먼저 파일별 행 수와 ID 중복을 확인하세요.
연결 전 96건 문의와 200건 방문이 연결 후 몇 행이 되었는지 비교하세요.
연결되지 않은 문의를 임의로 방문했다고 판단하지 마세요.
결과 표에는 연결 성공, 연결 실패, ID 불일치, 데이터 부족을 구분해 주세요.
```

**이렇게 나오면 성공:** 문의 원본 96행·방문 원본 200행을 보존하고, 확인된 문의 연결 30건을 별도로 표시한다. 두 파일의 행을 무심코 곱해 매출을 중복 집계하지 않는다.
