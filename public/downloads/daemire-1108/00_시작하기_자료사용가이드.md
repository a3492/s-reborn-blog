## 1. 상담에서 방문과 결제까지 — 실제 업무 흐름 이해하기

김민지가 인스타그램 DM으로 문의한다 → 상담원이 응대한다 → 네이버 예약 또는 전화로 예약한다 → 데스크가 베가스CRM에 고객·예약을 등록한다 → 진료실에서 시술 내용을 입력한다 → 데스크에서 결제 내역을 확정한다 → 다음 방문 때 기존 고객관리번호로 다시 접수한다.

각 단계의 기록이 **자동으로 하나의 표로 합쳐지는 것은 아니다.** 동일 고객 확인 절차, 직원의 기록, 서비스별 데이터 내보내기 범위가 필요하다.

| 접수 경로 | 실제 현장에서 생길 수 있는 기록 | 병원에서 별도로 정할 관리번호 예 | 자동 연결 시 주의점 |
|---|---|---|---|
| 인스타그램 DM | 계정명, DM 내용, 발신 시각 | `IGDM-20261001-001` | 플랫폼에서 발급한 실제 원본 ID 형식이 아니라 병원 내부 번호 |
| 카카오톡 채널 | 채팅 내용, 상담 시간, 채널상 프로필/표시명 | `KAKAO-20261001-001` | 서로 다른 채널의 계정이 같은 사람인지 자동 판별 불가 |
| 네이버 예약 | 예약 신청·변경 상태, 예약일, 서비스별 허용 정보 | `NAVER-20261001-001` | 서비스가 제공하는 예약번호와 병원 내부 번호를 구분 |
| 전화 | 통화 시각, 상담원 메모, 예약 여부 | `CALL-20261001-001` | 통화내역이 상담내용까지 자동 기록한다는 뜻은 아님 |
| 구글폼 | 제출 시각, 병원이 만든 질문과 응답 내용 | `GFORM-20261001-001` | 폼 행 번호가 환자 번호는 아님 |
| 베가스CRM 직접입력 | 고객관리번호, 접수·시술·결제 등 실제 설정에 따른 항목 | `VEGAS-20261001-001` | 프로그램 설치 버전·권한에 따라 항목과 연동 방식 다름 |

**번호 읽는 법:** `IGDM`은 경로코드, `20261001`은 2026년 10월 1일, `001`은 그날 해당 경로의 첫 번째 접수라는 뜻이다. 이 형식은 강연의 병원 내부 관리 규칙 예시이지 해당 서비스 공식 번호 형식이 아니다.

## 2. 문의관리번호·고객관리번호·방문관리번호는 무엇이 다른가?

- 문의관리번호 `INQ-202610-0001`: 상담 문의 **한 건**에 붙인다. AI가 연습자료를 만들 때 자동 생성한 번호다. 실제 채널에서 조회하거나 수집한 번호가 아니다.
- 경로별접수번호 `IGDM-20261001-001`: 문의가 유입된 경로·날짜·순서를 표시하는 **병원 내부 번호**다.
- 고객관리번호 `P0001`: 같은 사람이 문의를 여러 번 하거나 방문을 여러 번 하더라도 병원에서 동일 고객이라고 확인한 경우 사용한다.
- 방문관리번호 `VIS-202610-0001`: 내원 **한 번**마다 붙는다. 한 고객에게 여러 개가 있을 수 있다.
- 연결문의번호: CRM 방문이 어떤 문의로 이어졌는지 내부 확인 근거가 있을 때만 채운다. 빈칸은 '문의가 없었다'가 아니라 '확인된 연결 정보가 없다'는 뜻이다.

실제 병원에서는 개인 식별이 필요한 업무와 AI 분석용 파일을 분리한다. 원본은 병원 권한 내에서 보관하고, 분석할 파일에는 환자명·전화번호·이메일·생년월일·주소·자유서술 민감정보를 제거한다. 연결이 필요하면 내부 승인 절차로 만든 임의의 분석 전용 키를 사용한다. 이름을 그대로 넣거나 이름과 날짜만으로 환자를 연결하지 않는다.

## 4. 그대로 따라하는 여섯 단계

### 1단계 — 원본이 표로 바뀌는 과정을 먼저 읽고 파일 다운로드

이 자료와 `01_고객정보_수집경로별_원본예시와_자동정리.md`를 먼저 읽은 다음, `2026년10월_방문시술매출_CRM.xlsx`, `2026년10월_상담문의_목록.csv`를 다운로드한다. Windows에서 파일을 찾기 어렵다면 파일 탐색기의 다운로드 폴더를 연다. Excel에서 날짜가 숫자로 보이면 셀 서식을 날짜로 변경한다.

**이렇게 나오면 성공:** CRM 200개 방문 기록, 문의 CSV 96개 기록이 열린다.

### 2단계 — ChatGPT 열기

브라우저에서 ChatGPT를 열고 새 대화를 만든다. 파일 분석이 지원되는 환경인지 확인한다.

**이렇게 나오면 성공:** 새 채팅 입력창이 보인다.

### 3단계 — 파일 첨부하기

입력창의 파일 첨부 메뉴에서 `2026년10월_상담문의_목록.csv`를 선택한다. 파일명이 메시지에 보이는지 확인한다.

**이렇게 나오면 성공:** 전송 전 첨부된 파일명이 보인다.

### 4단계 — 질문 복사하여 붙여넣기

아래 문장을 통째로 복사하여 입력창에 붙여넣는다.

```text
첨부한 2026년 10월 상담문의 목록을 읽어 주세요.
첫 줄은 제목입니다. 제목을 제외한 행 수를 확인하세요.
문의유형별 건수와 전체 대비 비율을 계산하세요.
표 마지막에 전체 합계를 넣고, 집계한 건수가 실제 행 수와 같은지 확인하세요.
임의로 누락된 값을 만들어 채우지 마세요.
```

**이렇게 나오면 성공:** 총 96건, 시술·가격 문의 48건, 예약·변경 문의 12건, 부작용·회복 문의 8건, 기타 문의 28건.

### 5단계 — 분석 결과 검산하기

```text
방금 답변을 검산해 주세요.
분류별 건수를 다시 계산하여 합계가 96인지 확인하고, 비율도 재계산해 주세요.
빈칸과 중복된 문의관리번호가 몇 건인지도 알려 주세요.
확실하지 않은 값은 추측하지 마세요.
```

**이렇게 나오면 성공:** 48+12+8+28=96, 분류별 비율은 약 50.0%, 12.5%, 8.3%, 29.2%다.

### 6단계 — 방문·매출 파일과 함께 분석하기

CRM 파일도 첨부한 뒤 다음 문장을 붙여넣는다.

```text
상담문의와 CRM 방문시술매출 파일을 함께 분석해 주세요.
각 파일에서 제목 행을 제외한 행 수와 고유 ID 수를 먼저 확인하세요.
문의관리번호와 연결문의번호가 동일할 때만 두 기록을 연결하세요.
연결된 건에서 고객관리번호도 서로 일치하는지 확인하세요.
일치하지 않으면 연결 실패로 표시하고 임의로 매칭하지 마세요.
연결된 문의 수, 연결되지 않은 문의 수, 방문 원본 행 수를 각각 표로 보여 주세요.
문의와 방문이 1대1인지도 확인하고 연결 때문에 매출이 중복 합산되지 않았는지 검산하세요.
```

**이렇게 나오면 성공:** 방문 원본 200행과 문의 원본 96행을 정확히 구분하고, 확인된 연결 30건을 설명한다.

## 5. 내 병원 데이터로 바꾸려면

1. 각 채널 운영 화면과 베가스CRM에서 **허용되는 방법**으로 필요한 자료를 내보낸다. 직접 내보내기가 없다면 병원 내부 승인 후 최소 항목만 직원이 정리한다.
2. 시트별로 `접수경로`, `접수일`, `문의유형`, `예약상태`, `고객관리번호`, `방문일`, `시술명`, `결제금액` 등 필요한 항목만 정리한다.
3. 환자명·휴대전화·카카오 계정·DM 핸들·주소·이메일·상담 원문 등 식별·민감 정보는 분석 목적에 맞게 제거하거나 적법하게 비식별 처리한다. 단순 해시만 한다고 무조건 익명화되는 것은 아니다.
4. 내부 승인된 기준으로 각 채널 번호와 CRM 번호를 연결하는 **병원 내부 매핑표**를 만들되, 매핑표 원본은 외부 AI에 올리지 않는다.
5. 분석 파일을 별도로 만들어 소규모로 검산한다. 외부 AI 업로드 가능 여부는 병원의 계약, 보안 정책, 법률·개인정보보호 의무에 따라 먼저 검토한다.
