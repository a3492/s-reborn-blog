# S-Reborn CRM AI 실습 라이브러리 v2 — 리뉴얼 기획 및 변경 기록

## 목적과 상태
- 사용자가 코드만 보고 길을 잃는 문제를 해결하고, 실습 자료를 장기적으로 확장한다.
- 실행 완료(초기 반영): PP01~PP05 상세 설명 페이지, 기존 70개 실습의 공개 코드 PP형식, 구형 P/A~J 앵커 호환, 페이지 테마 로컬 저장값 동기화, 밝은 `.pain-group` 및 연관 표면 수정, 강연 허브 링크.
- **미완료:** 완전한 데이터 기반 시나리오 생성, 사이트 홈 최상위 바로가기, 실제 브라우저와 모바일 QA, Cloudflare 운영 배포 완료 검증. 이 항목은 별도 수행과 검증이 필요하다.
- 별도 URL: `/tutorials/crm-scenarios/pain-points/` / `/tutorials/crm-scenarios/`.

## 정보 아키텍처
1. 홈(향후 간편 접근 카드) → CRM AI 실습 라이브러리 (지속 확장)
2. 시작 화면에 두 경로를 동등하게 제공: **문제부터 이해** / **바로 실습**
3. 문제 유형 설명: PP01 고객 이해·상담 준비 / PP02 문의·예약·결정 / PP03 의료 안전·사후관리 / PP04 직원·운영 개선 / PP05 경영·데이터 분석
4. 각 유형 상세: 현장 현상 → 왜 문제인가 → 근본 원인 → AI 도움 범위 → 사람 승인/의료 안전 → 대표 실습
5. 실습 상세: 목적 → 합성 원문 다운로드 → AI 분석 프롬프트 → 기대 결과 → 원문 검증 → 실패 대응 → 다음 행동·완료 기준

## 콘텐츠 ID 결정
- 페인 포인트 코드 = `PP01`, `PP02` … 확장 시 `PP06` 등을 추가한다. 코드에 우선순위나 난이도를 의미 부여하지 않는다.
- 시나리오 표준 코드 = `PP01-01` 등. 한 번 배정한 코드는 변경하지 않는다.
- 과거 A~J 원본 ID의 표시명은 제거하고, URL 앵커만 호환용으로 유지한다.
- 과거 `P01-01` 앵커도 남겨 기존 URL이 깨지지 않도록 한다.
- **파일 호환:** 기존 `public/downloads/crm-scenarios/Pxx-yy.txt` 파일의 물리 경로는 그대로 보존한다. 화면상 표준 ID는 PP이다. 이후 메타데이터 분리 과정에서 표준 파일명 마이그레이션을 별도 작업으로 진행한다.
- 새 실습은 처음부터 `PPxx-yy` 표준을 사용한다. alias 배열을 수동이 아닌 단일 레지스트리에서 관리한다.

## 테마 문제 원인과 규칙
- 홈은 `BaseHead.astro`가 `localStorage['sreborn-theme']`(system/light/dark)로 테마를 결정한다.
- 기존 CRM 페이지는 `prefers-color-scheme`만 사용해 **홈에서 다크를 수동 선택해도 그대로 연동되지 않았다**.
- 다크 CSS는 `.scenario` 등에만 적용되고 `.pain-group`, `.pain-filter`, `th`, `.result`, `details` 등 일부 표면에 밝은 배경이 남았다. 흰 배경·흰 글씨 현상의 직접 원인이다.
- 반영한 1차 수정: 같은 저장 키 사용 + `html[data-theme]` 적용 + 모든 주요 컨테이너를 공통 표면 토큰으로 정리.
- 정식 목표: Astro 공통 레이아웃 + 디자인 토큰 `--bg, --bg2, --text, --rule`을 직접 공유하여 독립 CSS의 중복 제거. 네이비/민트는 실습 강조색으로만 사용한다.
- 수용 테스트: OS system light/dark, 수동 light/dark, 모바일 320/390/768 px, 데스크톱, 대비 4.5:1 (일반 글자), 키보드 포커스, 버튼/텍스트·표의 배경-글자 대비. 캡처에서 지적된 재현 사례를 회귀 테스트에 추가한다.

## 70개 이후 확장 아키텍처(계획)
- 별도 정의 `pain-points.json`: id, name, definition, symptoms, causes, effects, AI scope, human approvals.
- 각 시나리오는 구조화된 메타데이터: id, pp_id, title, learning_objective, synthetic_source, prompt, expected_output, verification, failures, completion, status, revision, aliases.
- 정적 HTML 1개에 전부 붙이는 방식에서 템플릿+데이터 기반 빌드로 마이그레이션. 콘텐츠 수는 레지스트리에서 자동 계산.
- 검색: 문제 설명/키워드/시술 단계/난이도/역할 태그; 코드 몰라도 찾는 검색.
- 신규 콘텐츠 제작: 아이디어 등록 → 기존 내용과 중복 점검 → 합성 사례 생성 → AI 프롬프트 초안 → 사람 승인 → 자동 QA → 브라우저 QA → 배포 → 라이브 접속 검증.
- 실환자 자료 업로드 금지 및 응급 의료 신호 인계 명시. AI는 의료 판단과 직원에 대한 평가를 자동 확정하지 않는다.

## 완료 기준
- 70개 PP 코드 및 설명과 내비게이션의 매핑 정확함.
- 과거 A~J 및 Pxx-yy 해시가 적절한 PP 시나리오로 이동됨.
- 가상 자료 다운로드 파일 70개 확인, 분석·검증 복사 기능 작동.
- 5개 페인 포인트 가이드로 왕복 탐색 가능.
- 테마 전체 시나리오 화면에서 화면 밝기/가독성 불일치 0건.
- 신규 시나리오 한 건 추가할 때 수동 카운트 편집이나 동일 HTML을 여러 번 고치지 않아도 됨.
- Cloudflare 성공 표시와 실제 서비스 URL 반환을 각각 검증.
