The following is a fictional scenario for illustration.

A notice said, "Saturday reservations are accepted by phone only." Asked to simplify it, AI returned, "Online reservations are also available on Saturdays." The wording was friendly, but sending it unchanged would misinform visitors. Understanding AI starts with **distinguishing a readable answer from a correct answer**.

**In one sentence:** AI enables computers to perform tasks such as classification, prediction and generation based on input. People decide how to use and verify the output.

## Look at the inputs and results

"Find inquiries about Saturday reservations" and "Write a Saturday reservation notice" sound similar, but the outputs differ. The first selects existing inquiries; the second creates new text. Before asking AI, write down **what goes in and what should come out**.

Sometimes a rule written by a person is simpler. A clear exception, such as phone-only Saturday bookings, can be enforced in the booking interface. When inquiries vary, such as "Is Sat available?" and "Book me for the weekend," a tool that groups similar meanings using learned patterns may help. Either way, check actual policy against the operator's original instructions.

## Distinguish the task you are assigning

Many AI models learn recurring patterns from examples. Given a new input, a trained model produces output suited to the task. One tool may contain multiple capabilities, so focus on **the task**, not its product name.

## Check one notice yourself

Choose a notice without personal information. Keep the original open beside the draft.

> Rewrite this notice in two sentences for first-time visitors. Preserve booking methods and exceptions. Do not add information missing from the original; list anything requiring confirmation separately.

Compare **day and time → booking method → exceptions**. If Saturday's rule is wrong, copy the phone-only condition from the source and correct it. Start with public material or practice sentences. Do not enter patient information or internal records into personal tools.

## Run a first experiment with the same notice

Add a condition: "Saturday bookings are by phone only; closed Sunday." Then make two requests.

1. First ask only, "Make this easier to read," and save the response.
2. Next ask, "Preserve Saturday's booking method and Sunday's closure, and quote the source for each condition."
3. Even if both sound good, underline Saturday / phone only / Sunday / closed and check each one. If any is missing, correct the draft against the original before using it.

If the first answer happens to be perfect, the experiment has not failed. Compare how easily you could verify the conditions in each response. "Can I see the source wording again?" is a reusable criterion. Explore [Prompt and context topics (Korean)](/blog/topics/prompting/) to practice adding conditions.
