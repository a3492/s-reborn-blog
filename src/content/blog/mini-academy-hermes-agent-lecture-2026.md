# AI에게 손과 발을 달아주는 시간

**Hermes로 직접 만드는 나만의 AI 에이전트**  
오프닝 질문: **“AI는 언제부터 스스로 일하기 시작했을까?”**

교육 목표: (1) LLM·에이전트·하네스·오케스트레이션 구분, (2) Hermes 설치와 한 번의 정상 실행, (3) 도구 사용과 결과 검증, (4) 메모리와 스킬 재사용, (5) 멀티에이전트 도구 선택 원칙.

## 진행 방식: 문제 → 역사/원리 → 즉석 실행 → 결과 검증

### 1막 — “AI는 말만 잘한다?”
- **질문:** “지난 3개월 신규 고객의 재방문율이 왜 떨어졌나?”라는 질문에 모델만 연결하면 무엇이 부족할까?
- **이론:** LLM은 모델, 에이전트는 모델에 도구·상태·실행 제어를 결합한 시스템이다. 자동화된 고정 절차와 동적으로 다음 행동을 결정하는 에이전트를 구분한다.
- **시연:** 가상 CSV를 분석하는 작업을 수행하고 최종 산출물이 실제 파일로 존재하는지 확인한다.
- **전환 대사:** “답을 얻은 것이 아니라, 일을 끝낸 것입니다.”

### 2막 — AI 엔지니어링의 진화
- 프롬프트 엔지니어링: 입력과 제약을 설계한다.
- RAG·컨텍스트 엔지니어링: 필요한 정보를 제때 제공한다.
- 추론 유도·ReAct·도구 사용: 판단과 관찰을 반복한다.
- 하네스·워크플로·에이전트 엔지니어링: 모델 바깥의 실행 환경, 권한, 상태, 재시도, 평가를 설계한다.
- **주의:** 이는 학습을 돕는 구성 순서이며 엄밀한 기술 발명 연대순이 아니다. 고전적 에이전트 연구는 LLM 등장보다 앞선다.

### 3막 — Hermes 설치와 모델 연결
1. 발표용 Windows PC에서 **공식 사이트의 Desktop 설치 경로**를 기본으로 사용한다. CLI가 필요한 경우 공식 설치 문서의 운영체제별 방법을 확인한다. 출처를 알 수 없는 설치 스크립트는 실행하지 않는다.
2. 기본 설정은 `hermes setup` 또는 공식 문서에 기재된 해당 시점의 온보딩 절차를 따른다. `hermes model`에서 사용 모델을 선택한다.
3. **첫 성공 조건:** 짧은 테스트 질문에 한 번 정확히 응답한다. 이 단계가 실패하면 다음 기능을 추가하지 않는다.
4. 모델별 사용량·비용·API 인증은 구독과 다를 수 있으므로 사전에 개별 계정에서 점검한다.
5. Windows 사용자는 기본 데스크톱 설치와 WSL 환경의 차이를 명확히 구분한다.

### 4막 — 도구: 손과 발
- 샘플 CSV 읽기 → 표본 수 확인 → 지표 계산 → 보고서 파일 작성.
- 파일 접근은 데모용 작업 폴더에만 허용한다. 시스템 명령의 자동 승인은 기본 비활성화한다.
- MCP는 연결 프로토콜이며 그 자체가 에이전트나 추론 모델은 아니다.
- **강조:** 에이전트가 도구 호출에 성공했다고 분석이 올바르다는 뜻은 아니다.

### 5막 — 메모리와 스킬
- 컨텍스트: 이번 실행에서 모델에 제공되는 정보.
- 지속 메모리: 세션이 끝나도 유지·검색 가능한 정보.
- 스킬: 여러 번 재사용하는 절차적 지침이나 실행 자산.
- 사용자가 선호하는 보고서 형식: “분석기간 / 데이터 정의 / 핵심 KPI / 확인된 변화 / 원인 가설 / 검증해야 할 항목 / 권고”를 고정한다.
- 다음 가상 데이터셋에서도 형식이 재현되는지 시험한다.
- **주의:** 외부 메모리의 갱신을 모델 가중치의 실시간 학습과 혼동하지 않는다.

### 6막 — 목표부터 결과 검증까지
**시연 프롬프트**

> 이 폴더에는 실제 환자정보가 아닌 가상 CRM CSV가 있습니다. 신규 고객의 30일 내 재방문율이 이전 기간보다 변했는지 분석하세요. 최초 방문의 기준, 재방문 기간, 관찰 종료일, 동일 고객 중복 제거 조건, 분모·분자를 먼저 정의하고 계산하세요. 관찰 기간이 부족한 고객은 별도로 표시하세요. 누락값·중복 행을 점검하고, 결과를 표와 한 페이지 보고서로 저장하세요. 원인으로 단정할 수 없는 것은 가설로 구분하세요. 외부 전송·원본 파일 수정·고객 연락은 하지 마세요.

**의도적인 함정:** 마지막 30일 동안 처음 방문한 고객은 충분한 관찰 기간이 없는 경우가 있다. 이 고객을 무조건 분모에 넣으면 재방문율이 인위적으로 낮아질 수 있다. 관찰 완결성 여부를 확인시키는 데 활용한다.

### 7막 — 오케스트레이션: 다음 단계
| 도구 | 강연에서 보여줄 주제 | 주의 |
| --- | --- | --- |
| Hermes Agent | **이번 강연의 핵심 실습**, 도구·메모리·스킬·반복 실행 | 공개 문서 기준 설치·보안 사전 검증 |
| OpenClaw | 개인 AI 보조자, 메신저 연결, 게이트웨이와 다중 채널 | 노출 포트·인증·권한 설정 |
| Orca | 여러 에이전트 세션과 작업 공간을 관리하는 계열의 도구 | 정확한 제품/버전과 기능 실사 필요 |
| **Herdr** | 동시 실행 및 오케스트레이션 비교 후보 | **Herd와 다른 명칭**. 공식 제품 주소·기능 확인 전 구체 기능을 확정하지 말 것 |
| Paseo | 에이전트 관리·원격 감독 비교 후보 | 공식 제품 주소·지원 범위 재확인 필요 |

이 제품들은 동일 계층의 부품으로 1:1 치환되는 것이 아니다. 일부는 에이전트 런타임, 일부는 사용자 인터페이스·게이트웨이·오케스트레이션을 동시에 다룬다. 기능 차이는 실물 데모 및 공식 문서로 재검증한다.
