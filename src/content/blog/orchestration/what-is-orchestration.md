금요일 오후, 서진은 회진을 준비하는 가상의 RoundPrep 팀에서 브리핑 초안을 시연했다. 화면에는 “추가 전달 사항 없음”이 떴다. 정보 담당 혜준이 원본을 열었다. 야간 전달 파일은 비어 있는 게 아니라 아직 열리지 않은 상태였다. 서진은 초안 가장 먼저 읽어야 할 줄을 바꿨다. “자료가 안 왔는지, 읽었는데 내용이 없었는지 먼저 알려 주세요.”

**한 줄 요약.** 오케스트레이션은 여러 AI·도구·사람이 한 작업을 끝내도록 **누가 무엇을 어떤 순서로 하고, 실패하면 어디로 넘길지** 정하는 일이다.

## 먼저 승인할 산출물을 정한다

RoundPrep 팀의 첫 목표는 합성 자료로 **회진 전달 브리핑의 초안**을 만드는 것이었다. 일정과 공지의 요약, 출처, 확인 여부를 초안에 함께 적는다. 치료 판단이나 실제 기록 시스템의 변경은 이 연습 범위에서 제외했다. 산출물이 정해지면 무슨 도구가 필요한지, 무엇을 자동으로 이어도 되는지가 보인다.

## 작업을 그리는 네 가지 질문

| 질문 | 설계 요소 | RoundPrep의 선택 |
| --- | --- | --- |
| 누가 무엇을 만드는가? | 단계 | 수집 도구는 원본 목록을, AI는 출처가 있는 초안을 만든다. |
| 어떤 자료를 기다려야 하는가? | 의존성 | 일정표·메모는 따로 읽고, 초안은 두 자료의 상태를 확인한 뒤 쓴다. |
| 어디까지 끝났는가? | 상태 | 자료별로 ‘수신’, ‘미수신’, ‘검토 완료’를 구별해 남긴다. |
| 멈추면 누가 이어받는가? | 복구 | 일시 오류만 재시도하고, 자료 누락은 담당자에게 넘긴다. |

팀은 ‘미수신’을 명시하고 자동 공유를 끊었다. 나중에 자료가 들어오면 이미 확인한 일정표까지 다시 불러올 필요 없이, 실패한 단계부터 재개한다. 초안이 완성돼도 담당자가 원문과 대조해 승인하기 전에는 공유되지 않는다.

## 내 업무로 옮기는 첫 연습

공개 회의 안건이나 합성 메모로 작은 흐름 하나를 그려 보자. 각 화살표 위에 **무엇을 넘기는지** 쓰고, 단계 옆에는 **실패하면 누가 받는지** 쓴다. 실제로 파일 하나를 빼고 실행해 보세요. 화면에 ‘미수신’이 뜨고, 담당자에게 설명할 수 있으면 첫 설계의 중요한 부분을 시험한 셈이다.

이미 손에 있는 공개 문서 한 장을 한 번 요약하는 일이라면 단일 요청으로 시작해도 충분하다. 같은 일을 반복하고 여러 입력, 확인 절차, 실패 복구가 필요해질 때 흐름을 명시하자.
